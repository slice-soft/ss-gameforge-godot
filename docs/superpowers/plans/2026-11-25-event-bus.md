# ss-gameforge-event-bus Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a typed, per-game event bus addon: a base `EventBus` class that each game extends with its own signals.

**Architecture:** `EventBus extends SingletonNode` (one instance per subclass script, `.i` accessor written by the subclass). The base adds `listen`/`unlisten` with a per-owner registry that is cleared on the owner's `tree_exiting`, plus a debug-only `trace` that hooks every signal the subclass declares.

**Tech Stack:** Godot 4.5+ (dev project targets 4.7; local binary is 4.5), GDScript, release-please.

**Spec:** `docs/superpowers/specs/2026-11-25-event-bus-design.md`

## Global Constraints

- Branch `feat/47-event-bus` off `release`. PR to `release`, titled `feat(event-bus): ... (#47)`. **Do not merge**: the user reviews it.

- GDScript only, tabs for indentation, same file layout as `ss-gameforge-toast`.
- Tests live in `tests/` (excluded via `.git/info/exclude`) and are **never committed**. Run them headless only.

- No visible Godot window without telling the user first.

## Review Focus

1. **Pooled / re-added nodes**: after `tree_exiting` the owner's subscriptions are gone, so re-entering the tree must not deliver events until the owner calls `listen` again. Docs must say to call `listen` in `_enter_tree`, not `_ready`, because `_ready` runs only once. Test: `test_reenter_requires_relisten` (Task 1).
2. **Owner freed without ever being in the tree** (`listen` on an orphan node): no error, and the registry entry is dropped on the next `unlisten`/`listen` sweep. Test: `test_orphan_owner_freed` (Task 1).
3. **Callable on another object** (a lambda, or a method of a child): `unlisten(owner)` still disconnects it, because the registry is keyed by owner, not by callable target. Test: `test_unlisten_disconnects_foreign_callable` (Task 1).
4. **Two subclasses of EventBus in one game**: each keeps its own instance (SingletonNode keys by script). Test: `test_two_buses_are_independent` (Task 1).
5. **trace in a release build**: no hook or prints when `OS.is_debug_build()` is false. Test: `test_trace_off_by_default` (Task 2); the release-build branch is covered by code review only.

### Task 2: Debug trace

**Files:**
- Modify: `addons/ss-gameforge-event-bus/core/event_bus.gd`
- Test (local): `tests/unit/test_event_bus.gd`

**Interfaces:**
- Consumes: `EventBus`, `trace` (Task 1)
- Produces: when `trace` is true in a debug build, each emission prints exactly one line: `[EventBus] <signal_name>(<args joined by ", ">)`, e.g. `[EventBus] pair(1, x)`.

- [ ] **Step 1: Add failing tests**. The bus exposes `func _format_trace(signal_name: StringName, args: Array) -> String`, so tests can assert on it without capturing stdout.

  - `test_trace_format`: `_format_trace(&"pair", [1, "x"]) == "[EventBus] pair(1, x)"`, and `_format_trace(&"pong", []) == "[EventBus] pong()"`.
  - `test_trace_hooks_only_subclass_signals`: after `trace = true`, `_trace_hooks` holds exactly `["pair", "ping"]` (sorted), not Node's built-in signals.
- [ ] **Step 2: Run and confirm FAIL.** Same command as Task 1; expected: the 3 new tests fail.
- [ ] **Step 3: Implement.**
  - `trace` gets a setter: on `true` (and `OS.is_debug_build()`), hook each signal from `get_script().get_script_signal_list()` with a variadic logger `func _on_traced(...args: Array)`. Pass the signal name with `.bind(name)`; it arrives as the last element of `args`. On `false`, remove the hooks.
  - Keep `var _trace_hooks: Dictionary` (name → Callable) so hooks are never doubled.
  - The logger calls `print(_format_trace(...))`.
- [ ] **Step 4: Run and confirm PASS** (all Task 1 and Task 2 tests).
